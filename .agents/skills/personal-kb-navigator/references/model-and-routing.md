# 模型与取材路线（参考）

> 本文件是 `SKILL.md` §3/§4/§5 的展开：**导航层清单与读取时机、各库职能细表、取材顺序**。
> 下文路径均为**示例实例（七库一说明）**的写法，且相对 `KB_ROOT`；套用到其他知识库时，以该库 `<KB_ROOT>\AGENTS.md` 的实际结构为准，不要照搬库名与路径。

## 1. 导航层清单与读取时机

| 导航文件 | 示例位置（相对 `KB_ROOT`） | 什么时候读 |
|---|---|---|
| 素材调用地图 | `4-素材案例库\00-总入口\素材调用地图.md` | 要把一条事实素材扩写成个人故事、课程案例或文章开头时 |
| 方法论调用地图 | `5-方法论库\方法论调用地图.md` | 搭 SOP / 课程 / 智能体 / 工作流，需要可复用方法时 |
| 写文章调用地图 | `6-内容生产\00-总入口\写文章调用地图.md` | 想写文章或朋友圈，需确定任务类型并按顺序取材时 |
| 成文与作品调用地图 | `6-内容生产\00-总入口\成文与作品调用地图.md` | 要找当前写作状态，或已完成、已发布作品的入口时 |
| 历史作品主题地图 | `6-内容生产\00-总入口\公众号历史作品主题地图.md` | 想按「未来要写什么」聚合回看历史文章时 |
| 客户需求调用地图 | `3-客户需求库\01-需求画像与总览\客户需求调用地图.md` | 写产品文案 / 发售文案 / 答疑话术，要用客户真实语言核对需求时 |
| 当前产品事实表（非「地图」，但同属导航 / 核对入口） | `2-产品库\01-产品体系与权益\当前产品事实表-待补.md` | 要核对产品 / 权益 / 价格 / 交付方式 / 当前状态 / 风险时 |
| 知识库日常使用入口 | `6-内容生产\00-总入口\知识库日常使用入口.md` | 「不知道知识库怎么用时」的第一入口 |

> **计数口径**：上述文件共同构成知识库的「导航层」，其中「调用地图」为一类（素材 / 方法论 / 写文章 / 成文与作品 / 历史作品 / 客户需求），另含各库「总入口」与「当前产品事实表」。为避免口径漂移，描述数量时统一用**「各库调用地图与总入口」**——不下具体数字，也不要把产品事实表误计为「地图」。
>
> **为什么不下固定数字？** 导航类文件随知识库演进会增删（源说明本身即无统一计数口径）；写死数字必然过时，并与 `SKILL.md` §11「『地图』计数别硬编」的告警自相矛盾。

## 2. 三类调用地图的细节

### 2.1 素材调用地图（示例：`4-素材案例库`）

需要把一条**事实素材**扩写成个人故事、课程案例或文章开头时先读它；并配合方法论库中的「故事写作：用目标、障碍、行动和变化承载主题」类方法。

> **约束**：主题只能帮助**选材**，不能改写事实。

### 2.2 方法论调用地图（示例：`5-方法论库`）

收纳**可复用方法**（而非单次感想）。典型分类：内容创作、AI 工作流、产品设计、营销与销售、咨询交付、关系沟通与个人成长、团队与 SOP、时间管理、读书与学习方法、复盘与目标管理。

### 2.3 写文章调用地图（示例：`6-内容生产`）

写文章前的**取值顺序**：

```
本文件确定任务类型
  → 老板说明书（校准人物与表达）
  → 素材案例库（找故事与证据）
  → 方法论库（找方法论）
  → 产品库 与 客户需求库（校验产品和用户）
```

含多条调用路线：素材能力、卡片与朋友圈、读者与需求、故事与案例、成文与作品。

### 2.4 成文与作品调用地图（示例：`6-内容生产`）

三个入口分工：

| 入口 | 角色 |
|---|---|
| `ss成文监控：代表作` | 一篇代表作的活动工作区（保存目标 / 素材 / 版本 / 短版 / 过程） |
| `ss成文日志` | 当前写作状态与「正在写什么」的轻量记录 |
| `历史：我的作品集` | 按时间和主题保存已完成、已发布作品入口 |

当前回源位置（示例）：`7-其他备用\01-原始备份\<外部记录工具原文>\ss写作系统（原文）.md`。

### 2.5 历史作品主题地图（示例：`6-内容生产`）

解决「历史文章目录适合回源，却不适合从头浏览」：先按「**未来要写什么**」聚合入口。典型主题：写作与内容生产、阅读学习、目标任务与时间管理、知识管理与体系建设、人际成长与生活议题。

> **三种状态不要混用**：已发布且有链接 / 已写但未发布 / 只有题目或半成品。

## 3. 各库职能细表（示例实例）

| 库 | 职能 | 典型资产 |
|---|---|---|
| `1-老板说明书` | 我是谁、我的故事、表达风格、边界和判断 | 人物与表达校准资产 |
| `2-产品库` | 产品体系、权益、价格证据、发售历史和销售素材 | 产品事实与销售口径 |
| `3-客户需求库` | 客户原话、需求线索、反馈、未成交原因和咨询材料 | 真实语言的客户需求 |
| `4-素材案例库` | 朋友圈素材、个人故事、生活现场、客户案例、可调用证据 | 故事与证据素材 |
| `5-方法论库` | 内容创作、AI 工作流、产品设计、营销销售、咨询交付、团队 SOP | 可复用方法 |
| `6-内容生产` | 选题、成稿、文章索引、对标账号、生产流水线 | 生产流程与作品索引 |
| `7-其他备用` | 临时过渡区：原始备份、旧索引、处理工作台、输出产物、暂不确定归属的散件 | 施工与回源（非日常入口） |

## 4. 产品事实表字段

以示例实例的 `2-产品库\01-产品体系与权益\当前产品事实表-待补.md` 为例，按字段维护每个产品：

```
产品 / 适合谁 / 解决什么问题 / 权益 / 价格 / 交付方式 / 当前状态 / 风险
```

并列出**「不构成当前权益证据的资料」判据**与**历史资料回查入口**。核对产品前必须读它，而不是凭旧文案回忆。

## 5. 「你不需要做什么」

（原说明明确列出的免负担清单，属该类库的设计前提）

- 不需记住每个文件夹
- 不需自己判断每句话属于哪个库
- 不需为了整齐把所有旧文拆成卡片
- 不需同时维护外部记录工具和本地两份相同正文
- 不需阅读 AI 生成的所有施工文件
- 不需把历史价格、权益和旧目标手动清理干净后才能使用
