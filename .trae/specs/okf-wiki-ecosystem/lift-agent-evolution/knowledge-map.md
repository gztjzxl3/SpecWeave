# 知识地图

## 事实层

- 页面与文章：账号、原创标记、发布时间、文章主张（F-001–F-006）。
- 官方机制：Warmup/Holdout、Base/Loaded 配对、状态隔离、任务结构、requirements 重合度与 Judge 流程（F-013–F-017、F-028）。
- 指标与证据边界：指标、delta 公式、重复次数、配对任务数、置信区间估计方法、turns 口径、排行榜快照和论文限制（F-008–F-012、F-018–F-023、F-029–F-031）。
- 领域语境：已有相关评测工作及仓库 license 信息缺口（F-024–F-026）。

## 机制层：四元组洞察

### 洞察一：Loaded Impact 衡量的是加载产物的增量，不是 Agent 的绝对能力

- **现象/结论**：LIFT 的核心比较是同一 Holdout 任务上的 Base 与 Loaded 差异。
- **证据**：F-013、F-014、F-019、F-020。
- **反常识点**：排行榜上更优的 delta 不等同于该 runtime 的绝对任务能力更强；衡量对象是“加载前后变化”。
- **影响**：若忽略配对基线，容易把相对变化误读为跨 Agent 的能力排名。
- **建议**：引用 LIFT 数字时同时报告 Base、Loaded、delta、任务集和 runtime；不单独拿 delta 作为总体能力分数。

### 洞察二：任务划分与状态隔离能降低直接泄漏，但不等于要求域完全未见

**现象/结论**：评测将 Warmup 与 Holdout 任务分开，并借助容器状态管理控制运行边界；但官方 suite 称两阶段 requirements 约有 75% 重合，其余为变体或矛盾要求。
- **证据**：F-013–F-015、F-028。
- **反常识点**：使用名为 Holdout 的集合，不自动意味着其要求空间与 Warmup 完全不相交。
- **影响**：将结果概括成“对全新任务要求的泛化”会超出该 suite 的划分证据。
- **建议**：报告具体区分任务级保留与要求级重合；借鉴该设计时冻结任务划分、运行环境和状态快照，并说明重合比例。

### 洞察三：重复次数和区间声明不能替代对数据新鲜度与实验覆盖度的检查

- **现象/结论**：排行榜声明 `n_repeats=10` 和 95% CI，runtime 条目另有 274–280 个配对 task-repeats；点估计与区间使用不同聚合层级，数据快照早于文章，论文也标记为部分跨 runtime 扫描。
- **证据**：F-008–F-012、F-019、F-021、F-029。
- **反常识点**：统计格式完整，不代表数据已覆盖当前项目状态，也不代表研究已经完成全部计划实验。
- **影响**：读者可能把静态旧快照读成文章发布时的最新成绩，或将部分 sweep 当成最终结论。
- **建议**：每次引用榜单同时写明 `generated_at`、名义 repeats、paired task-repeats 数、点估计和 CI 的计算口径及论文版本状态。

### 洞察四：Judge 与环境保真度属于测量系统的一部分

- **现象/结论**：论文把 Judge 偏差和容器环境与真实使用环境的差异列为局限。
- **证据**：F-015、F-017、F-022。
- **反常识点**：评测结果不只由 Agent 决定，裁判规则和执行环境也会塑造观测值。
- **影响**：若 Judge 偏向某种轨迹表达，或容器任务与真实浏览器/桌面工作差异较大，结果的外推范围会变窄。
- **建议**：把 Judge 一致性、环境覆盖和失败样例纳入评测报告；结论限定在实际测试环境。

## 迁移层：同题配对评测

**模式名：同题配对评测。成熟度：L1-draft，基于一个框架的设计与公开材料，尚非独立复现实证。**

- **适用场景**：要评估加载记忆、技能、策略或其他演化产物是否改善最终任务表现。
- **不适用场景**：目标是比较不同系统的绝对能力，或任务/环境无法建立可比的配对条件。
- **步骤**：
  1. 在 Holdout 之外准备演化阶段任务，并冻结 Holdout 任务。
  2. 为 Base 与 Loaded 条件使用相同 Holdout 输入、工具约束和判分规则。
  3. 明确隔离演化状态，记录镜像、环境和任务版本。
  4. 按预先声明的重复次数运行两种条件，报告原始值与配对差异。
  5. 区分名义重复次数与配对任务重复数，报告点估计、区间算法、Judge 规则、失败样例和外推限制。
- **检验标准**：两种条件任务一致；状态来源可追踪；重复次数和指标定义明确；原始值、delta 与不确定性同时公开。
- **反模式**：只报 Loaded 结果；用不同题目比较 Base 与 Loaded；重复使用训练任务充当 Holdout；把单次最好结果当稳定提升；将单一容器基准推广为所有真实环境的结论。
- **跨领域迁移**：可用于比较加载检索知识前后的问答系统、加载策略文件前后的流程 Agent，或加载规则配置前后的自动化系统；需保持成对任务与评测条件可比。

## 可复现性判定

1. **是否有定义输入、过程和可观察输出？** 有：官方材料定义任务字段、Base/Loaded 流程和效率指标（F-016–F-020）。
2. **是否能由独立执行者按文章本身重复验证？** 否：文章没有提供包含固定版本、环境准备、输入输出和完整运行步骤的独立复现剧本；官方项目资料可供进一步研究，但不把文章改写成未经验证的操作教程。

因此知识包不创建 `examples/`。
