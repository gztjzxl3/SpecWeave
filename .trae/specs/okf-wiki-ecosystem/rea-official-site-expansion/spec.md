# REA 中文官网全站学习与 OKF Wiki 更新

## 概述

- 目的：全面学习 REA 中文官网及子页面，将新增知识转化为可溯源、可操作的中文教程。
- 读者：逆向工程初学者、希望借助编程助手调查应用行为的开发者。
- 目标目录：`projects/awesome-okf-xs/doc/bundles/jishu/ai/products/rea/`。
- 基线：既有事实 F-001~F-135、10 篇概念文档与 6 篇示例；本轮增量扩展，不重建知识包。
- 工作流：七概念知识沉淀 R→I→E→V；实施前批准，完成后独立审查。Git 提交须另获用户明确授权。

## 目标与非目标

- 目标：全部中文内容页有采集记录、知识归属与覆盖说明；新增事实编号续接；教程提供前置条件、调查过程、证据与验证边界。
- 非目标：翻译其他语言重复页面、复制官网全文、安装 REA 或逆向引擎、实测未授权目标、修改 REA 源码、主动创建方法论模式或执行 Git 提交。

## 功能需求

- FR-1：以页面清单、访问日期、标题/章节和采集结果登记本轮官网信源；每页注明新增、既有覆盖或采集失败，不以访问首页代替全站覆盖。
- FR-2：逐页阅读正文，展开或读取正文提取器遗漏的折叠内容、代码与实验逻辑；新增事实从 F-136 起，不重复编号或覆写旧事实。
- FR-3：提炼有事实引用的洞察，按学习路径组织安装、首次调查、指南与案例；避免把不同页面的案例机制混为同一实验。
- FR-4：分批增量更新 concepts/examples；必要时新增独立主题文档，随后更新 references/index、各级内容索引与 log。
- FR-5：发现既有命令示例、来源行号或其他结论错误时，修正并留勘误轨迹；不以“命令名存在”代替完整参数验证。

## 非功能需求与约束

- NFR-1：中文原创归纳、标准相对链接、可解析 YAML；新增内容 sources 使用 `resource`，`okf_version` 仅放 bundle 根 index。
- NFR-2：区分官网在线快照、本地固定 commit `eaf88aca2af2b8ad7a277c09d0b45f6e2de8ac4a` 与历史案例版本。官网新版结论不无条件覆盖旧版本事实。
- NFR-3：上游自述成绩标注归属；数量核验记录统计口径。未执行的命令和实验明确标注“未在本机实跑”。
- NFR-4：临时采集、脚本与构建输出放工作区外；最终资料仅入目标 bundle，规划仅入本目录。
- NFR-5：子模块 merge/rebase 进行中禁止写入；保护其他会话变更，不修改无关共享索引、工具链或治理规则。

## 验收标准

### AC-1：中文站覆盖完整
- **Type**: `rule`
- **通过条件**：sitemap 中文页面集合与各页面发现的站内中文链接集合都被对账；每个内容页有访问结果、内容归属和覆盖记录。失败页不得计作已学习。
- **证据**：references 中的逐页清单、集合差异和失败记录。

### AC-2：事实与版本可追溯
- **Type**: `rule`
- **通过条件**：新增事实编号从 F-136 连续且唯一，每条指向实际读取的 URL/章节；数字标明来源与核验口径，案例版本与源码版本不混用；没有未标注推断。
- **证据**：facts、信源登记、数字与关键声明回验记录。

### AC-3：命令与教学边界准确
- **Type**: `rule`
- **通过条件**：本轮新增/修改命令的命令名、必填位置参数、选项与输入形态经对应官网文档或固定源码核对；没有把示意符号当真实函数名，没有把未实跑当验证成功。
- **证据**：命令核验表、examples 与勘误记录。

### AC-4：学习价值
- **Type**: `rubric`
- **维度**：从新手上手到证据驱动调查与重建的可用性。
- **量表**：1-5。
- **锚点**：1=网页摘要堆砌；3=主题齐全但前置/验证步骤不清；5=学习路径清楚、步骤有证据与结果判据、案例差异及限制明确。
- **通过阈值**：>=4。
- **证据**：教程、示例、洞察与页面到文档映射，独立审查评分。

### AC-5：文档完整性与独立审查
- **Type**: `rule`
- **通过条件**：相对链接可达、新增内容 frontmatter 合规、所有内容在 toctree 可达；UTF-8 与定向构建无本轮引入的错误；最新独立 Review 为 pass。全库外部阻塞明确隔离，不声称全库通过。
- **证据**：脚本输出、构建结果、review.md。
