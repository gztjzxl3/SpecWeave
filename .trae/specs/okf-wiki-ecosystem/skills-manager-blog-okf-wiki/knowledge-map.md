# Skills Manager 知识地图

## 归属与内容骨架

- **目标分组**：`jishu/ai/products/`。主线实体是 Skills Manager 产品；该分组已收录 AI 桌面工作台和任务型工具。`jishu/ai/practice/` 偏工程实践，语义不如产品组直接；不为单篇文章新建分组。
- **内容性质**：第三方产品介绍及机制概览，不是完整可复现的操作教程。
- **examples 两问**：
  1. 文章是否给出可照做的安装/配置/同步流程？**部分有**：提及平台、macOS 安装入口和若干界面路径，但没有逐平台完整步骤及适用版本。
  2. 独立执行者是否能据此重复并核验结果？**否**：文章无测试环境、明确版本、完整输入输出、冲突处理及恢复验证步骤；作者也未声明亲测。
- **结论**：不创建 `examples/`。概念文档可解释机制及边界，但不能把概述补写成文章实测或可直接照做的操作承诺。

## I 阶段洞察（四元组）

### 洞察 1：数量必须保留统计对象

- **现象**：截至 2026-10-10 的 README 写明“54 agents ... out of the box”，文章也称 54；仓库 API 描述为“50+ coding tools”。（F-007、F-021、F-023~F-024）
- **工作假设**：文章的数量得到当前 README 的直接支持，API 描述与其大致相容；但 `agents` 和 `coding tools` 是不同字段表述，不能据此假设统计集合完全相同。
- **影响**：旧核验曾因过期/误读的 README 与 Release 快照，错误地将文章数字标成未获官方支持，并低估版本；这会使后续读者看到自相矛盾的事实记录。
- **建议**：引用动态数量时保留来源字段、README commit SHA 和观察日期；不把静态快照当长期支持保证。（F-007、F-021、F-023~F-024、F-030~F-031）

### 洞察 2：备份安全取决于状态和平台路径

- **现象**：100 MiB 限制针对尚未纳入 Git 跟踪的超限技能；Windows 本地 NTFS 可用 junction 回退，但 UNC/WSL 路径采用复制回退。
- **工作假设**：产品在备份完整性和跨文件系统链接兼容性之间按具体状态/路径选择不同处理方式。
- **影响**：只读“超过限制会排除”或“Windows 使用 junction”容易误导读者，分别忽略已跟踪状态和远程路径限制。
- **建议**：将阈值、跟踪状态和目标文件系统分开核对；重要技能备份后检查仓库内容并执行恢复演练。（F-010、F-025、F-027~F-028）

### 洞察 3：凭证存储描述不等于安全审计结论

- **现象**：PAT/Device Flow 连接路径要求令牌写入操作系统钥匙串成功；旧式含凭证 URL 的净化路径在钥匙串不可用时会保留原 URL。文章未描述这两条源码路径的差异。
- **工作假设**：不同入口有不同失败行为；仅凭“使用系统钥匙串”不足以判定每种凭证路径和故障情形下的保护强度。
- **影响**：将单一存储机制概括为“凭证始终安全”会超出代码证据。
- **建议**：部署前检查所用平台的实际凭证后端和回退行为；对敏感仓库使用最小权限令牌，并遵循组织凭证政策。（F-016、F-026）
