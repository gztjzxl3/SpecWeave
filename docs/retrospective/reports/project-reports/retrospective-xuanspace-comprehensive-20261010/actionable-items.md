# 原子行动项：玄境（Xuanspace）全面复盘

> 本文件承载本轮复盘的 G4 产出：8 条原子行动项，每条单一职责、可独立验证，含优先级、Owner、触发条件/时间节点、验收标准与来源。洞察见 [insight-extraction.md](insight-extraction.md)，主报告见 [README.md](README.md)。

## 行动项清单

### ACT-01 常驻待办池 + spec 会话后继可执行项登记

- **描述**：建立常驻待办池（backlog）文件，并要求每个 spec 会话在其结束报告中登记"后继可执行项"（如 doctor 检查扩展、依赖巡检、文档同步、单点版本对齐），把可独立执行的小任务登记为可持续消费的队列，消除会话之间的纯空窗。
- **优先级**：高
- **Owner**：项目维护者
- **触发条件/时间节点**：下个 spec 会话结束时即启用；backlog 文件于下个迭代启动前建立
- **验收标准**：①backlog 文件存在且持续更新；②每个 spec 会话结束报告含"后继可执行项"清单，且 ≥1 条后继项/会话；③空窗期（连续 ≥3 天零提交）后可由 backlog 派发出至少一项可执行任务
- **来源**：I-1；F-055、F-061、F-107、F-110、F-128

### ACT-02 迁入即治理检查单纳入 `xs doctor` 自动核验

- **描述**：将"迁入即治理"检查单（构建后端对齐、`requires-python` 与根一致、版本声明单一源、文档形态对齐）固化为可机械判定的检查项，接入 `xs doctor`，复用并扩展现有的子模块指针检查与 Sphinx 路径检查。
- **优先级**：高
- **Owner**：项目维护者
- **触发条件/时间节点**：下个迭代周期内（迁入窗口关闭前）
- **验收标准**：`xs doctor` 新增一致性核验项，可对全部 20 个 `pyproject.toml` 输出"包 → 项 → 期望 vs 实际"的字段级结论，并打印"未解释偏离数"；该核验可在不检出上游的环境独立运行
- **来源**：I-2、模式 B §1.2 步骤 3；F-047、F-048、F-060、F-096

### ACT-03 全仓 `requires-python` 一致性对齐

- **描述**：对齐全仓（含第一方 libs 与 tools/templates）`requires-python` 声明与根一致为 `>=3.14.6`，或对每一处不一致建立登记条目与理由（视为"有意偏离"）。
- **优先级**：中
- **Owner**：项目维护者
- **触发条件/时间节点**：ACT-02 完成后一个迭代内
- **验收标准**：`xuan-compose`（F-082）与子模块 tvm-book/mystx（F-085）的 `requires-python` 不一致项或已对齐为 `>=3.14.6`、或已登记理由；`xs doctor` 一致性核验该项通过
- **来源**：I-2 建议 1；F-082、F-085、F-096

### ACT-04 上游同步强制"怪癖台账 diff 复核"门禁

- **描述**：对上游同步类 spec（如 `sync-upstream-delta`，F-110）强制增设验收门：同步后须逐条判定 `upstream-quirks.md` 台账条目的新增/升级/失效，输出台账 diff 复核结论，无结论不得归档。
- **优先级**：中
- **Owner**：项目维护者
- **触发条件/时间节点**：下一个上游同步 spec 立项时
- **验收标准**：该 spec 交付物含 `upstream-quirks.md` 台账 diff 复核结论（逐条判定新增/升级/失效）；缺失该结论的同步 spec 不得通过验收
- **来源**：I-3 建议 2、模式 A 并入差异点 3；F-110、F-114

### ACT-05 怪癖 L0-L3 分级上升为仓库级规范

- **描述**：将上游怪癖 L0-L3 分级口径从单文件约定（`upstream-quirks.md`）上升为 xuanspace 仓库级规范（写入 AGENTS.md 或构建/对等重构规范），使新迁入包默认遵循。
- **优先级**：中
- **Owner**：项目维护者
- **触发条件/时间节点**：下一个迁入包启动前
- **验收标准**：仓库级规范文本含四级定义（L0 精确断言 / L1 弱断言 / L2 注释固化 / L3 清单固化）与台账登记纪律（位点、触发条件、保留依据、"怪癖非设计契约"标注）；新迁入包的对等文档引用该规范
- **来源**：I-3 建议 1；F-114、F-115、F-116

### ACT-06 工作区快照双时点标注纪律

- **描述**：确立纪律——凡报告或结论涉及 `projects/xuanspace` 工作区事实，一律标注"采集时点 / 复核时点"并陈述差异，并明示"工作区快照不得作为确定性结论唯一依据"。
- **优先级**：中
- **Owner**：复盘/报告作者
- **触发条件/时间节点**：自本报告起立即生效
- **验收标准**：后续涉及工作区的报告均含双时点标注；凡以工作区为输入的单值结论均附时点与不确定性说明；本报告 F-070/F-128 即为合规范例
- **来源**：I-4 建议 2、V-6；F-070、F-128、F-129

### ACT-07 F-113 自报值的证据强度治理

- **描述**：凡引用 xuan-compose 对等门禁自报值（484 ≥ 478、skip=0、覆盖率 91%、142 符号 100% 映射）之处，一律标注"项目自报口径、未经重跑验证"，且一致性/对等性结论改以仓库文件实体为证据。
- **优先级**：中
- **Owner**：复盘/报告作者
- **触发条件/时间节点**：自本报告起立即生效
- **验收标准**：后续引用 F-113 数值的文档均带自报口径标注；任何以 F-113 为唯一依据的对等性断言被改写为"以各 `pyproject.toml`/符号清单实读为准"
- **来源**：V-5；F-113、F-082、F-096

### ACT-08 `apps/`、`attic/` 空壳目录状态标注

- **描述**：为 `apps/`、`attic/` 两个空壳目录明确"预留 / 孵化 / 归档"状态标注，写入其 README 或根文档，消除"存在即开发中"的模糊语义。
- **优先级**：低
- **Owner**：项目维护者
- **触发条件/时间节点**：下个文档维护周期
- **验收标准**：`apps/README.md` 与 `attic/README.md`（或对应根文档）明确标注该目录的状态类别与用途；可由 docgen/doctor 检出一致性
- **来源**：I-4 建议 3；F-089、F-093
